## 三、漏洞面

| 面 | 结论 |
| --- | --- |
| 运行期网络 | 零请求：无 fetch、无 XHR、无外链脚本、无 CDN、无 Worker。用户照片只在内存与本地 canvas 之间流动 |
| 第三方依赖 | 零依赖（无 package.json、无 node_modules）→ 没有供应链面 |
| 字符串求值 | 无 eval、无 `new Function` |
| 注入面 | `innerHTML` 仅 2 处，喂的都是仓内写死的 SVG 图标常量；所有用户可见文本走 `textContent` 与 `createTextNode` |
| 文件输入 | 只接受 `image/*`，读入即 `FileReader → Image → canvas`，不落盘、不上传；HEIF 解码失败时给明确提示而不是静默 |
| 存储 | `localStorage` 读写全部 try/catch 包裹，file:// 与隐私模式下降级为内存态，不影响功能 |
| CSP | 故意没加。加 `script-src 'self'` 会威胁"双击 index.html 就能用"这条底线（file:// 下 CSP 对本地脚本的判定在各浏览器不一致），而本站既无外部脚本也无用户输入回显，收益为零。若日后只做 Pages 部署，可以在托管层加响应头，比写在 meta 里稳 |
| 已知限制 | 8 bit 输入色深；无 RAW 解码；星图岁差用总岁进动近似（不含章动，误差 <0.01°）；镜头视场投影在 >60° 视场时形状畸变到 3% 量级 |

## 五、界面

界面回归由 `tools/shot.mjs` 代跑：无头 Electron 加载 `file://`，改系统明暗偏好来验"跟随系统"这条路，逐组截图并探测四件事——兜底卡有没有出现、控制台有没有报错、画布有没有真的画出亮像素、页面有没有横向溢出。共 17 组：五个视图 × 明暗 × 1440、首页与星图 × 412 窄屏、路书 × 900、精修拖放导入（并断言调参前后像素哈希必须变化）、星图穹顶与取景两套投影 × 明暗。当前 **17 组全过，0 失败**。

已经肉眼复核并因此回修的：

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 星图上一个星点都没有 | 星表步长从 `meta.stride` 之外取，半径算成 NaN | 改取值，画布亮像素计数复核 |
| 专名糊成一团 | 星等门槛判断失效，298 个名字全画 | 按亮度排序 + 文字实际占位区间避让 |
| 银河带看出笔触 | 四条粗描边直接叠在主画布上 | 改离屏绘制 + 一次性糊化 |
| 两个视图白屏 | `card()` 把子节点数组当成一个孩子传给 appendChild | UI 库改为递归展平，并把错误本身显示到界面上 |
| 点深色按钮界面不动 | 主题只认显式选择，从没走过"跟随系统"这条路 | 改为默认 auto 并读 `prefers-color-scheme`，回归脚本顺带把这条验成机器判据 |
| 首页光段刻度互相压字 | 标签按百分比绝对定位，字宽不参与计算 | 渲染后量真实宽度，三行错位排布，跟随窗口缩放重排 |
| 取景投影顶端一圈糊字 | 所有方位线在天顶收敛，标签全画在同一处并被上边缘裁掉 | 标签改挂到各线最接近画面中线的那一点，并按 x 间隔去重 |
| 打点分段按钮挤断字 | 分段条不换行且按钮内文字被压缩 | 允许换行 + 文字禁断行，直方图改整宽 |
| 光段条标签溢出贴边 | 一天 11 个光段全塞进刻度 | 只留 7 个关键刻度 |
| 首页评分卡排版歪 | 28px 大字号标题与仪表条基线不齐 | 改标题层级 + 仪表独占一行 |
| 精修面板套预设后崩 | 预设以 `normalizeRecipe` 为底，`geometry` 留成 null | 改以带空壳的 `newRecipe()` 为底并逐字段兜底 |
| 笔刷半径滑杆显示 0 | 界面态被当成配方字段读 | 改回界面态滑杆，并注明不进配方 |

**仍待人工确认一项**：精修页一次导出多张时，浏览器"允许下载多个文件"的放行提示。这是宿主行为，页面拿不到被拦截的回调，无头环境更测不出来。代码侧能做的是逐张间隔 900ms 触发、每张 toast 报进度、结束时明确报总张数，用户能立刻核对到没到手；真机确认留给第一次使用。窄屏与深色两套已由回归覆盖；iPhone Safari 真机未测，桌面 412px 与断点排版已验。
