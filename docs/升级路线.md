# 升级路线

缺口编号 `G-XX`，候选编号 `C-XX`。判据只有一条：**这件事会不会破红线**（零网络、零依赖、算不出来就留白）。破了红线的不是"暂缓"，是"换做法"或"不做"。

## 已知缺口

| 编号 | 缺什么 | 现在怎么办 | 为什么没做 |
| --- | --- | --- | --- |
| G-01 | RAW 解码 | 导出 `.cube` 交给 Lightroom / Capture One，色彩链不丢 | 要引第三方解码库，直接破"零依赖"。相机型号清单也是无底洞 |
| G-02 | 五官级人像（眼睛/牙齿/下颌线自动定位） | 肤色掩膜自动 + 打点手动（亮眼/白牙/黑眼圈/轮廓收扩） | 需要模型权重，破零依赖与零网络两条。代价：换脸级修图做不到，我们能做到的是"不糊不塑料" |
| G-03 | 云量、光污染、通透度自动取数 | 界面标"自填/需联网"：低云量与空气通透度是滑杆，光污染是 Bortle 1–8 | 破"照片不出本机"这条立身之本。真要做只能是显式开关 + 用户自己按，且默认关 |
| G-04 | 导出位深 8 bit | 预览与算子内部走线性空间，落盘 8 bit JPEG/PNG | 16 bit TIFF 能加，但会诱导人在我们这继续叠层，与"配方 + .cube 回 Lightroom"的定位相反 |
| G-05 | 批量导出的浏览器放行提示 | 逐张间隔 900 ms、toast 报进度与总张数 | 宿主行为，页面拿不到被拦截的回调。只能人第一次用时确认 |
| G-06 | iPhone Safari 真机 | 桌面 412px 与断点已由无头回归覆盖 | 无真机可跑；触控拖拽与 `localStorage` 配额需实测 |
| G-07 | 路书 → 精修 的闭环 | 路书能导出 Markdown/JSON，精修能导入图片，两边不互认 | 缺一个"机位 + 时刻 + 焦段"的中间件；先等真实使用反馈 |

## 明确暂不做

见 `像素蛋糕拆解.md` 的"我们故意不抄的"一节——批量证件照、AI 换天、全身塑形、云端渲染那几条不是能力不够，是选了另一条路。
